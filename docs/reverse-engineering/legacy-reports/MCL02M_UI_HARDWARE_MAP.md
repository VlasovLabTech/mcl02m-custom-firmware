# MCL02M: карта органов управления и индикации

Дата: 2026-08-22
Объект: интерфейсная ESP32-плата `chunmi.ihcooker.v2`
Метод: повторный статический анализ штатного ELF/flash dump и сопоставление с официальной схемой панели. Никакие команды нагрева, записи во flash или изменения eFuse в этом проходе не выполнялись.

## 1. Сравнение с официальной документацией

Официальное руководство Xiaomi для 米家电磁炉2 показывает тот же набор внешних элементов:

- главный вращающийся и нажимаемый энкодер со встроенным OLED;
- левая ёмкостная кнопка таймера;
- правая ёмкостная кнопка отмены; отдельно указано, что у неё нет собственного индикатора;
- дуга индикаторов мощности;
- нижний двухцветный сине-оранжевый **Wi‑Fi indicator**;
- пассивная NFC-метка.

Источник: <https://cdn.cnbj1.fds.api.mi-img.com/ics-resources/articles/60c9c192ad904a4ba1144ef9.html>

Документация не показывает отдельного красного LED или дополнительной пользовательской кнопки. Нижний оранжевый цвет штатно относится к Wi‑Fi-индикатору, а не является выделенным error LED. Прошивка может включать его в определённых состояниях, поэтому визуально он мог совпасть с ошибкой.

В ESP32-приложении не найден исполняемый NFC-драйвер или NFC-протокол. Это согласуется с отдельной пассивной меткой, открывающей ссылку/приложение. NFC не нужен для собственной прошивки и дальше не рассматривается.

## 2. Сводная карта

| Узел | Штатная линия/протокол | Уверенность | Основание |
|---|---|---:|---|
| Центральное нажатие `S1` | GPIO34, active-low | высокая | `KeyScanTask` постоянно читает GPIO34; на разъёме есть ровно `GND/S1` |
| Энкодер `KA/KB` | GPIO5 и GPIO14, ISR по обеим фазам | высокая для пары | два квадратурных callback формируют события `2/5`; точная фаза A/B требует калибровки |
| Левая/правая touch-кнопки | I²C1: GPIO19/GPIO18, 10 kHz, 7-bit `0x60`; альтернативно UART1 9600 | высокая | `i2c_master1_init`, чтение `0xC0/0xC1`; fallback UART |
| Обе touch-кнопки вместе | логический код `8` | высокая | UART-код `0x0A = 0x08 | 0x02` |
| OLED 64×48 | SPI host 1, 2 MHz | подтверждено runtime | физически проверены рамка и угловые фигуры, шахматка 8×8 (8×6 клеток), пять концентрических окружностей; framebuffer page-major `64×6` |
| OLED SCLK/MOSI | GPIO25/GPIO27 | высокая | `spi_bus_config` |
| OLED RESET | GPIO26 | высокая | reset-последовательность high-low-high перед init |
| OLED D/C | GPIO33 | высокая | SPI pre-transfer callback копирует `transaction.user` в GPIO33 |
| OLED CS | рабочая конфигурация GPIO0 | высокая | с аппаратным CS на GPIO0 корректно отображаются примитивы по всей матрице; это ещё не исключает вариант, что CS дисплея постоянно притянут и GPIO0 физически не подключён |
| Пищалка | GPIO23 | высокая | штатный tone/pattern driver инициализирует выход `0x17` |
| LED serial STB/CLK/SDN | GPIO17/GPIO16/GPIO4 | высокая | точное назначение в `FUN_401c0870(17,16,4,0,7)` и bit-bang код |
| Девять LED мощности | serial RAM bytes 0/1 и bit0 byte2 | высокая по логике, требует физического channel test | две 4-битные группы плюс один бит дают 9 каналов; таблица имеет 9 ступеней |
| Нижний blue/orange LED | bit1/bit2 byte2 serial driver | высокая для пары | оба бита управляются из Wi‑Fi state machine; точный цвет каждого бита ещё не назван |
| Таймерный LED/подсветка кнопок | GPIO22/GPIO32, точное назначение неизвестно | средняя | прямые UI-выходы, активно переключаются при смене режимов; не являются OLED reset/DC |
| Силовая плата | I²C0 GPIO13/GPIO15, 10 kHz, 7-bit `0x2A` | подтверждено runtime | отдельный от touch I²C-контур |

## 3. Разъёмы UI-платы

### Разъём 1: `STB, CLK, SDN, 5V`

Сопоставление по штатному коду:

| Контакт | ESP32 | Назначение |
|---|---:|---|
| STB | GPIO17 | строб/выбор команды LED-драйвера |
| CLK | GPIO16 | последовательный clock |
| SDN | GPIO4 | последовательные данные, LSB-first |
| 5V | питание UI-платы | до активного теста измерить реальный уровень и наличие level shifting |

Общий GND приходит через второй разъём. Штатная последовательность совместима с семейством трёхпроводных LED-драйверов TM16xx: mode command `0x00`, fixed-address command `0x44`, RAM addresses `0xC0/0xC2/0xC4`, display-control `0x8F`. Точный MPN микросхемы лучше считать с корпуса, поэтому в собственной прошивке драйвер следует называть нейтрально `ui_led_serial`.

### Разъём 2: `GND, S1, KA, KB`

| Контакт | ESP32 | Назначение |
|---|---:|---|
| GND | GND | общий |
| S1 | GPIO34 | центральная кнопка, active-low, внешний pull-up |
| KA | GPIO5 или GPIO14 | фаза энкодера |
| KB | GPIO14 или GPIO5 | фаза энкодера |

Связь пары `KA/KB ↔ GPIO5/GPIO14` доказана архитектурой и callback-кодом. Какой из двух контактов является GPIO5, определяется одной прозвонкой; если просто поменять их местами в ПО, изменится только знак вращения.

## 4. Что, вероятно, идёт через OLED flex

Поскольку кроме двух разъёмов и flex-шлейфа связей между платами нет, через flex должны идти не только линии OLED, но и остальные UI-сигналы:

- OLED: GPIO25, GPIO27, GPIO26, GPIO33 и вероятный GPIO0;
- touch controller: GPIO18/GPIO19;
- прямые UI-выходы GPIO22/GPIO32;
- питание и земля.

Это объясняет прежнюю неопределённость: боковые touch-кнопки не проходят через разъём `S1/KA/KB` и не читаются через LED-driver.

## 5. Стоковая логика ввода

- GPIO34 обслуживается отдельным press/hold/release FSM.
- Пороги `40` и `150` циклов используются для long-press/repeat; цикл заканчивается задержкой `2` FreeRTOS ticks.
- Энкодерные ISR на GPIO5/14 формируют события `2` и `5`, то есть два направления вращения.
- Touch controller выдаёт два индивидуальных кода и их комбинацию. До аппаратной проверки безопасно называть их `TOUCH_A`, `TOUCH_B`, `TOUCH_BOTH`, а не заранее назначать left/right.
- Новая тестовая прошивка не должна связывать ни одно из этих событий с нагревом или UI-выходами: только журналирование и телеметрия.

## 6. Оставшиеся короткие аппаратные проверки

1. При полностью снятом питании прозвонить `KA/KB → GPIO5/GPIO14`.
2. Если потребуется абсолютная уверенность, прозвонить физическую линию OLED CS; программная конфигурация GPIO0 уже проверена как рабочая.
3. Измерить idle/high уровни `STB/CLK/SDN` на штатной плате и убедиться, что входы UI-драйвера принимают 3.3 V при питании 5 V.
4. Коротким поканальным тестом определить `bit1/bit2 → blue/orange`.
5. Коротко включить GPIO22 и GPIO32 по одному и определить timer/backlight mapping.

Все эти тесты возможны без подключения силовой платы и без I²C-команд нагрева.
