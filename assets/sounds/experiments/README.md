# MCL02M buzzer sound design

Первый пробный набор коротких 8-bit-мелодий для пассивной пищалки
GPIO23. Частоты обычных мелодий ограничены примерно `0.8–4.7 kHz`: заявленный
провал громкости `6–8 kHz` не используется.

| Файл | Событие | Длительность | Характер |
|---|---|---:|---|
| `01_power_on.wav` | включение | 3.25 s | весёлый восходящий boot |
| `02_cooking_complete.wav` | готовка завершена | 2.75 s | короткая победная фанфара |
| `03_no_pan.wav` | снята посуда | 2.20 s | вопросительный, неаварийный сигнал |
| `04_critical_error_motif.wav` | критическая ошибка | 2.50 s | резкий аварийный мотив |
| `05_sleep.wav` | сон | 3.97 s | замедляющаяся нисходящая мелодия |

`previews/00_all_melodies_in_order.wav` воспроизводит их в порядке таблицы с
паузами 1.5 секунды. WAV синтезирован меандром, как PWM пищалки, но с коротким
fade только для защиты компьютерных динамиков от щелчков. Реальная громкость и
тембр зависят от механического резонанса пищалки и корпуса плитки.

`melody_tables.generated.h` содержит готовые тройки
`{frequency_hz, on_ms, gap_ms}`. Они пока не подключены к production firmware:
сначала мелодии нужно прослушать и при необходимости поправить.

Критический файл — один мотив длительностью 2.5 секунды. При интеграции два таких
мотива должны образовать примерно 5-секундный burst, а существующий безопасный
контур `3 bursts / 4 s gaps / always audible / ACK stops immediately` должен
остаться. Это позволяет получить нужную музыкальную фразу, не ослабляя аварийную
сигнализацию.

Пересборка превью:

```powershell
py -3 .\generate_previews.py
```

## V2: более игровой вариант

`generate_previews_v2.py` и `previews_v2` содержат второй, более выраженный
NES/Game Boy-вариант. Он остаётся полностью монофоническим и состоит только из
PWM-нот `{frequency_hz, on_ms, gap_ms}`, но использует быстрые арпеджио,
синкопированные ритмы, хроматические проходы и более характерные игровые
концовки. Первый набор сохранён для прямого сравнения.

Готовые таблицы второго набора записываются в
`melody_tables_v2.generated.h`. Пересборка:

```powershell
py -3 .\generate_previews_v2.py
```

## V3: общеизвестные мелодические основы

V3 полностью меняет концепцию и связывает каждое событие с подходящей ему
мелодией из общественного достояния:

- включение — «Коробейники» с новой arcade power-up концовкой;
- завершение — «Ода к радости» с новой level-clear cadence;
- NoPan — вступление «К Элизе» как просьба обратить внимание;
- критическая ошибка — ритм Пятой симфонии Бетховена;
- сон — колыбельная Брамса с новой замедляющейся концовкой.

Это собственные монофонические PWM-аранжировки, запрограммированные по нотам;
записи и конкретные игровые аранжировки не копировались. V1 и V2 сохранены,
production firmware по-прежнему не изменена.

```powershell
py -3 .\generate_previews_v3.py
```

## V4: ещё более строгая привязка к событиям

- boot — оригинальная торжественная 8-bit fanfare;
- complete — очень радостная традиционная `When the Saints Go Marching In`;
- NoPan — резкий тритоновый low-health alarm с хроматическим падением;
- critical — знаменитое вступление Токкаты ре минор BWV 565 Баха;
- sleep — низкая и редкая `Ah! vous dirai-je, maman / Twinkle Twinkle`.

Sleep пока использует тот же 50% duty в таблице нот. Для реального тихого звука
при интеграции нужно расширить `ui_buzzer_chirp()` параметром duty и использовать
для sleep примерно 15–20%. Его WAV-превью приглушено вдвое, чтобы приблизительно
показать задуманный характер; никаких PCM-данных в таблице для ESP32 нет.

```powershell
py -3 .\generate_previews_v4.py
```

## Выбранный пакет

`generate_selected_pack.py`, `SELECTED_PACK.md` и `previews_selected` собирают
подтверждённые владельцем варианты из V3/V4 под едиными финальными именами и
добавляют отдельную короткую мелодию пробуждения. Production firmware пока не
подключена к этим таблицам.
